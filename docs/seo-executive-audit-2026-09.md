### Выводы из данных

1. **Роль-запросов («услуги для CEO») в Wordstat нет.** Подтверждается: у фраз
   вида «услуги для генерального директора» частота ~0. Руководителя надо
   перехватывать на языке проблемы: «автоматизация отдела продаж»,
   «контроль качества работы менеджеров», «как внедрить ии в компании»,
   «как убрать ручной ввод данных». Поэтому роль-страницы построены вокруг
   проблемных формулировок, а не вокруг слова «CEO».
2. **Основной объём спроса — «автоматизация», а не «ИИ».** «автоматизация бизнес
   процессов» (3357) на порядок больше, чем весь ИИ-кластер вместе. Позиционирование
   «AI, CRM и автоматизация бизнес-процессов под ключ» соответствует спросу;
   позиционирование «нейросети» — нет.
3. **Кластер документов недооценён:** «автоматизация документооборота» 850 +
   «ии обработка документов» 379 + «автоматизация документооборота компании» 38.
   Это прямая зона COO — отсюда отдельная страница `/for-coo`.
4. **Enterprise-кластер (private LLM, on-premise, закрытый контур) низкочастотный,
   но с максимальным чеком.** Держим на `/secure-ai` + `/for-cio`, не размывая
   по десяткам URL.
5. **Ассоциации Wordstat («similar») в этом срезе шумные** — «разработчик игр»,
   «центр реализации», «ооо интеграция». Для решений использовать только
   `source=popular`.

Реализовано в `src/lib/seo-redirects.ts` (301, без цепочек — проверено):

/solutions/business-process-automation  → /services/business-process-automation

/solutions/1c-ai                        → /integrations/1c-ai-layer

Почему алиасами, а не новыми страницами: перечисленные кластеры уже имеют
страницу-владельца с накопленной видимостью («корпоративный rag»,
«купить и внедрить rag в россии», «внедрение ии в бизнес под ключ»).
Создание второй страницы под тот же интент — каннибализация и риск
«Малополезный контент» в Вебмастере. URL-схема при этом рабочая:
любая внешняя ссылка на `/solutions/corporate-rag` попадает на владельца кластера.

Порядок первых экранов (проверено в билде):
оффер → цена «от 150 000 ₽» + пилот 1–3 недели → доверие/партнёрства →
проблемы бизнеса → **задачи руководителей** → направления внедрения с ценами →
демо «до/после» → кейсы с цифрами → ROI-калькулятор → пакеты → качество сборки →
FAQ → форма с квалификацией.

Форма уже собирает всё, что требуется для квалификации: компания, сайт компании,
должность, имя, контакт, процесс, используемые системы, размер команды, бюджет,
срок запуска.

CTA на сайте: «Обсудить задачу», «Получить оценку», «Рассчитать экономику
внедрения», «Разбор одного процесса». «Напишите нам» / «бесплатная консультация»

## 5. Техническое SEO

Проверка: `npm run seo:tech` (по живому хосту), `npm run webmaster:seo`.

Исправлено в этом заходе:

- **`/faq` не отображал контент**: страница рендерила 35 пустых карточек, потому что
  namespace `faq` держит вопросы в `items` как `{q, a}`, а компонент ждал `{title}`.
  Теперь вопросы и ответы выводятся текстом и попадают в `FAQPage`-разметку.
  Это была thin page по прямому коммерческому запросу «сколько стоит внедрение ии»;
- **orphan pages**: `/blog` не ссылался ни на один из 65 постов, `/guides` — ни на один
  из 5 гайдов (хабы отдавали только статичный текст). Оба хаба переписаны как
  реальные индексы с `ItemList`-разметкой и перелинковкой в коммерческие страницы;
- `/faq` и все страницы на `ContentSectionPage` получили `WebPage` + `FAQPage` JSON-LD
  (раньше — без разметки вовсе);
- URL главной в sitemap приведён к каноническому виду без завершающего слэша
  (совпадает с `absoluteUrl("/")` и с `rel=canonical`);
- список проверяемых лендингов в `scripts/seo-tech-check.mjs`: убран
  `/integrations/bitrix24` (301 → `/bitrix`), добавлены четыре роль-страницы;
- роль-страницы добавлены в `PRIORITY_PATHS` sitemap и в
  `YANDEX_IMPORTANT_PATHS` (мониторинг важных страниц в Вебмастере).

Уже в порядке: canonical на всех страницах, breadcrumbs + `BreadcrumbList`,
OpenGraph, `Organization` / `Person` / `Service` / `WebSite` JSON-LD,
301 вместо дублей, исключение редирект-источников из sitemap,
`Clean-param` для utm/yclid, apex → www.

Остаётся на живом хосте (деплой-зависимое, не код): секция
`User-agent: Yandex` в отданном robots.txt (в репозитории `Allow: /` есть),
и `/info.md` без title/description — это markdown-файл, ложное срабатывание
проверки.

2. **Dify — статья, не лендинг.** «dify» 1571 при нулевом коммерческом интенте:
   `/blog/dify-vnedrenie-alternativy` с таблицей сравнения Dify / n8n / Flowise /

3. **Короткие URL из предложенной схемы — алиасами**, а не новыми страницами:

### Чего сознательно не делали

10–30 новых лендингов под перечисленные кластеры не создавали: по данным Wordstat
там нет 10–30 самостоятельных интентов — есть 1 незакрытый кластер (агенты),

фразу означает отдавать Яндексу выбор канонической страницы и ронять обе.
